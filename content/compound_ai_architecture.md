# Compound AI System 상세 아키텍처 설계

Compound AI System 의 표준적인 보안 및 품질 보장 아키텍처를 정확히 반영하고 있습니다.

각 단계가 단순한 선형 구조를 넘어, 앞서 논의한 **비용 최적화**와 **품질 보장** 원리가 어떻게 유기적으로 결합되는지 상세 설계 관점에서 정리해 드립니다.

---

## 🏗 Compound AI System 상세 아키텍처 구성

이 시스템은 **단일 LLM 에 의존하지 않고, 여러 컴포넌트가 협력하여 신뢰성을 높이는 구조**입니다.

```
┌─────────────────────────────────────────────────────────────────┐
│                        User Input                               │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  1. Input Guardrail (입력 가드레일)                              │
│     - Prompt Injection 방어                                     │
│     - PII Masking                                               │
│     - 유해/무의미 질문 필터링                                    │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  2. Intent Classifier & Router (의도 분류기 & 라우터)            │
│     - 모델 계층화 (SLM vs LLM)                                  │
│     - Semantic Caching 체크 (Short-circuit)                     │
└─────────────────────────────────────────────────────────────────┘
                              ↓
              ┌───────────────┴───────────────┐
              ↓                               ↓
┌─────────────────────────┐     ┌─────────────────────────┐
│  Simple Task (SLM)      │     │  3. RAG Pipeline        │
│  - 단순 인사/상식       │     │     - Retrieval         │
│  - 경량 모델 처리       │     │     - Re-ranking        │
│                         │     │     - Context Grounding │
└─────────────────────────┘     └─────────────────────────┘
              ↓                               ↓
              └───────────────┬───────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  4. AI Gateway (AI GW)                                          │
│     - Load Balancing & Failover                                 │
│     - Rate Limiting                                             │
│     - Prompt Caching                                            │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  5. Output Guardrail (출력 가드레일)                             │
│     - 환각 체크 (Self-Correction)                               │
│     - 구조화 출력 검증                                          │
│     - 민감도 필터링                                             │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                        Final Response                           │
└─────────────────────────────────────────────────────────────────┘
```

---

## 1. 입력 가드레일 (Input Guardrail)

**시스템의 첫 번째 방어선**으로, 부적절한 입력이 내부 로직을 소모하기 전에 차단합니다.

### Prompt Injection 방어

- 모델의 시스템 설정을 무력화하려는 시도를 감지합니다.

### PII Masking

- **개인정보 **(주민번호, 계좌번호 등)하여 익명화 처리합니다.

### 비용 절감

- 유해하거나 무의미한 질문을 여기서 걸러내어, 이후 단계의 **고비용 GPU/API 자원 낭비**를 방지합니다.

---

## 2. 의도 분류기 (Intent Classifier) & 라우터

사용자의 질문을 분석하여 **최적의 처리 경로**를 결정합니다.

### 모델 계층화 적용

- **단순 인사나 일반 상식** → 경량 모델 (SLM) 로
- **복잡한 전문 지식** → RAG 파이프라인으로 보냅니다.

### 시맨틱 캐싱 체크

- 분류 직후, **벡터 DB 를 조회**하여 동일/유사 질문에 대한 기존 응답이 있다면 **즉시 반환 **(Short-circuit)하여 비용을 0 으로 만듭니다.

---

## 3. RAG 파이프라인 (Retrieval-Augmented Generation)

모델의 **'환각'을 방지**하고 전문 지식을 주입하는 핵심 구간입니다.

### Retrieval

- 질문과 관련된 **최신 문서를 지식 베이스 **(Vector DB)합니다.

### Re-ranking

- 검색된 결과 중 **가장 관련성 높은 상위 K 개만 선별**하여 입력 토큰을 최적화합니다.

### Context Grounding

- 추출된 정보만을 바탕으로 답변을 생성하도록 **모델에게 제약을 겁니다**.

---

## 4. AI Gateway (AI GW)

**다양한 LLM 공급자와의 연결을 관리**하는 통합 인터페이스입니다.

### 로드 밸런싱 & Failover

- 특정 API(OpenAI 등) 의 장애 시 **타 모델 **(Anthropic, Gemini 등)하여 가용성을 보장합니다.

### Rate Limiting

- 사용자/서비스별 **쿼리 제한을 통해 비용 폭주**를 방지합니다.

### Prompt Caching

- 게이트웨이 레벨에서 **공통 프롬프트를 캐싱**하여 입력 비용을 절감합니다.

---

## 5. 출력 가드레일 (Output Guardrail)

모델이 생성한 **최종 답변의 품질과 안전성을 검증**합니다.

### 환각 체크 (Self-Correction)

- 생성된 답변이 RAG 로 제공된 **근거 문서와 일치하는지 LLM-as-a-Judge 를 통해 검증**합니다.

### 구조화 출력 검증

- **JSON 등 정해진 형식을 지켰는지 확인**하고, 실패 시 검증 루프를 통해 재생성을 요청합니다.

### 민감도 필터링

- 모델이 부주의하게 내뱉을 수 있는 **내부 기밀이나 부적절한 표현을 차단**합니다.

---

## 📊 구성 요소별 핵심 역할 요약

| 구성 요소 | 적용 원리 | 기대 효과 |
|----------|----------|----------|
| **가드레일 **(In/Out) | 품질 보장, 보안 | 시스템 안정성 및 컴플라이언스 준수 |
| **의도 분류기** | 모델 계층화 | 난이도별 최적 모델 매핑 (비용 절감) |
| **RAG 파이프라인** | 환각 방지 | 도메인 특화 지식 확보 및 신뢰도 향상 |
| **AI Gateway** | 인프라 최적화 | 멀티 모델 운영 효율성 및 가용성 확보 |
| **응답 반환** | 구조화 출력 | 후속 시스템 (Legacy 시스템) 과의 연동성 |

## 💡 엔지니어링 포인트: PDCA 적용 제언

설계하신 이 아키텍처가 실무에서 성공하려면 다음의 검증 루프를 고려해 보시기 바랍니다.

### AAR (After Action Report)

> **출력 가드레일에서 거부된 응답들을 분석**하여 입력 프롬프트나 RAG 의 검색 품질을 수정합니다.

### 비용 모니터링

> **AI GW 에서 발생하는 모델별 토큰 소모량을 대시보드화**하여, 특정 작업에서 고비용 모델을 저비용 모델로 교체할 수 있는지 상시 검토합니다.

## 감리 관점에서의 시사점

정보시스템 감리 관점에서 Compound AI System 아키텍처 검토 시 고려사항:

1. **다중 방어 체계 검증**: Input/Output Guardrail 의 정책 규칙과 업데이트 메커니즘
2. **라우팅 정확도**: Intent Classifier 의 분류 정확도와 모델 매핑 적절성
3. **캐시 효율성**: Semantic Caching 히트율과 Short-circuit 성공률 측정
4. **RAG 품질**: Retrieval 정확도, Re-ranking 효과성, Grounding 준수율
5. **가용성 관리**: AI Gateway 의 Load Balancing, Failover 테스트 결과
6. **비용 통제**: 모델별 토큰 소모량 모니터링과 최적화 이력 추적
7. **검증 루프 운영**: 환각 체크, 구조화 출력 검증, 재생성 성공률 분석
