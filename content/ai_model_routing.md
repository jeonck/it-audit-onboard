# AI 모델 라우팅 전략 (Model Routing Strategies)

AI 기반 소프트웨어 아키텍처에서 **모델 라우팅 (Model Routing)**은 효율성과 성능이라는 두 마리 토끼를 잡기 위한 핵심 관문입니다.

요청의 특성에 따라 최적의 모델로 경로를 지정하는 **4 가지 핵심 전략**을 상세히 정리해 드립니다.

---

## 1. 규칙 기반 라우팅 (Rule-based Routing)

사전에 정의된 명시적 조건 (If-Then) 에 따라 요청을 배분하는 **가장 단순하고 확실한 전략**입니다.

### 작동 원리

요청의 메타데이터 (**API 엔드포인트, 사용자 등급, 데이터 크기, 언어 설정** 등) 를 기준으로 모델을 할당합니다.

### 적용 예시

| 조건 | 라우팅 대상 |
|------|------------|
| **VIP 사용자** | 항상 최상위 모델 (Claude 3.5 Sonnet) 로 연결 |
| **입력 텍스트 ≤ 1,000 자** | 소형 모델 (Llama 3 8B) 로 처리 |
| **영어 입력** | 영어 특화 모델로 라우팅 |

### 장점

- **예측 가능성이 높고 지연 시간 (Latency) 이 거의 없습니다.**

### 단점

- 복잡하고 모호한 사용자 질문의 의도를 파악하기 어렵습니다.

---

## 2. 의도 기반 라우팅 (Intent-based Routing)

사용자의 질문이 **무엇을 목표로 하는지 **(Intent)를 먼저 분석한 후, 해당 작업에 특화된 모델로 전달합니다.

### 작동 원리

메인 모델 호출 전, **매우 가벼운 분류 모델 **(Classifier)이나 **임베딩 기반 검색**을 통해 의도를 파악합니다.

### 적용 예시

| 의도 | 라우팅 대상 |
|------|------------|
| **코드 작성** | 코딩 특화 모델로 라우팅 |
| **단순 인사/일상 대화** | 초경량 SLM(Small Language Model) 으로 처리 |
| **복잡한 데이터 분석** | 고성능 추론 모델로 라우팅 |

### 장점

- **각 도메인에 최적화된 모델을 사용하여 품질을 극대화**할 수 있습니다.

### 단점

- 분류 레이어가 추가로 필요합니다.

---

## 3. 비용 최적화 라우팅 (Cost-optimized Routing)

설계하신 아키텍처에서 가장 중요한 요소 중 하나로, **정해진 예산 내에서 최대의 효율**을 내도록 설계합니다.

### 작동 원리

**실시간으로 모델별 토큰 단가와 현재 가용 예산**을 확인하여 모델을 선택합니다. 특히 출력 토큰 단가가 높은 모델의 사용을 최소화하는 방향으로 작동합니다.

### 적용 예시

| 전략 | 설명 |
|------|------|
| **Prompt Caching 활용** | 캐싱된 데이터와 유사도가 높은 요청은 해당 캐시를 보유한 모델로 우선 배분 |
| **Batch 처리** | 실시간성이 낮고 양이 많은 작업은 **50% 저렴한 배치 API 채널**로 자동 라우팅 |

### 장점

- **운영 비용을 획기적으로 절감**하며, 인프라 지속 가능성을 확보합니다.

### 단점

- 실시간 비용 모니터링 인프라가 필요합니다.

---

## 4. 케스케이드 라우팅 (Cascade Routing)

여러 모델을 계층적으로 배치하여, **하위 모델이 실패할 경우에만 상위 모델로 '폭포수'처럼 요청을 넘기는 방식**입니다.

### 작동 원리

1. 먼저 **저렴하고 빠른 모델**이 응답을 생성합니다.
2. 이후 **검증 루프 **(Self-Correction)를 통해 응답 품질이 기준치 미달일 경우, 더 고성능의 비싼 모델에게 다시 작업을 요청합니다.

### 적용 예시

| 시나리오 | 설명 |
|----------|------|
| **신뢰도 기반** | GPT-4o mini 가 먼저 답변 생성 → '신뢰도 점수'가 70 점 미만이면 GPT-4o 가 재생성 |
| **RAG 격상** | 간단한 RAG 결과 도출 시도 후, 정보가 부족하면 Agentic RAG 로 격상 |

### 장점

- **평균 응답 비용은 낮게 유지하면서도, 고난도 질문에 대한 품질을 보장**합니다.

### 단점

- 재요청 시 지연 시간이 증가할 수 있습니다.

---

## 💡 전략별 비교 요약

| 전략 | 핵심 기준 | 주요 장점 | 비고 |
|------|----------|----------|------|
| **규칙 기반** | 메타데이터 (ID, 크기 등) | 결정론적, 낮은 지연 시간 | 가장 정적인 방식 |
| **의도 기반** | 작업의 성격 (분류, 생성 등) | 도메인 특화 품질 최적화 | 분류 레이어 필요 |
| **비용 최적화** | 토큰 단가 및 예산 | 운영 효율성 극대화 | 캐싱 전략과 병행 권장 |
| **케스케이드** | 응답의 신뢰도/품질 | 비용 대비 고성능 보장 | 재요청 시 지연 시간 증가 |

## 🎯 Compound AI System 적용 제언

엔지니어님의 **Compound AI System 설계**에 이 라우팅 전략들을 적용한다면:

```
1. 의도 분류기 단계에서
   → 의도 기반 + 비용 최적화 라우팅 혼합

2. 최종 응답 생성 단계에서
   → 케스케이드 적용

3. 결과
   → 환각 방지와 비용 절감을 동시에 달성
```

## 감리 관점에서의 시사점

정보시스템 감리 관점에서 모델 라우팅 도입 시 고려사항:

1. **라우팅 규칙 투명성**: 모델 선택 기준과 우선순위 규칙의 문서화 및 감사 추적성
2. **분류 정확도**: 의도 분류기의 정확도와 오표류 (Misrouting) 영향도 분석
3. **비용 통제 효과**: 라우팅 전략 적용 전후 토큰 비용 비교 및 절감률 측정
4. **품질 일관성**: 케스케이드 재요청 시 응답 품질과 지연 시간 트레이드오프 관리
5. **페어니스**: 사용자 등급별 차등 라우팅의 윤리적·정책적 적절성 검토
6. **장애 대응**: 모델 장애 시 Failover 라우팅과 복구 절차 마련
