# AI-DLC (AI-Driven Development Lifecycle) 3 단계

AI-DLC (AI-Driven Development Lifecycle) 의 3 단계는 AWS 가 주도적으로 제안한 **AI 네이티브 개발 방법론**의 핵심 구조입니다.

기존 SDLC 를 AI 시대에 맞게 재구상한 것으로, **AI 가 프로세스의 중심 (주도적 계획·제안·실행) 에 서고, 인간은 검증·의사결정·감독 역할**을 맡는 패러다임입니다.

2026 년 현재 가장 널리 참조되는 표준 3 단계는 다음과 같습니다. (AWS 공식 블로그 및 한국어 번역 자료, GitHub whitepaper 등 기반)

---

## AI-DLC 의 3 단계 개요

| 단계 | 영문 이름 | 한국어 번역 | 핵심 질문 | AI 의 주요 역할 | 인간의 주요 역할 | 주요 산출물 / Ritual | 목적 요약 |
|------|----------|------------|----------|----------------|-----------------|---------------------|----------|
| **1 단계** | Inception | 착수 / 인셉션 / 기획 | **무엇을 만들고 왜 만드는가?** | 비즈니스 의도 → 요구사항 분석, 명확화 질문, 사용자 스토리 자동 생성, Unit(작업 단위) 분해 | 전체 팀 (Mob Elaboration) 으로 AI 질문 검증·답변·방향 조율 | 사용자 스토리, NFR(비기능 요구사항), Risk, Unit 정의 | 의도 (Intent) 포착 + 검증된 맥락 축적 |
| **2 단계** | Construction | 구축 / 구성 | **어떻게 만들 것인가?** | 검증된 맥락 기반으로 도메인 모델, 논리 아키텍처, API 설계, 코드·테스트 자동 생성·제안 | 기술 결정·아키텍처 선택 실시간 검토·가이드 (Mob Construction) | 도메인 모델, 코드 솔루션, 단위 테스트, 비기능 설계 | 구현 가능한 Deployment Unit 완성 |
| **3 단계** | Operations | 운영 / 오퍼레이션 | **어떻게 운영·유지할 것인가?** | IaC(코드형 인프라), 배포 자동화, 모니터링·관찰 가능성 설정, Telemetry 기반 자율 개선 제안 | 최종 승인, 운영 감독, 예외 대응 | 배포 파이프라인, Runbook, 모니터링 설정, AI 기반 사전 문제 해결 | 프로덕션 운영 + 지속적 최적화 |

## 각 단계의 세부 특징 (2026 년 실무 기준)

### 1 단계: Inception (착수/기획)

- **AI 가 먼저 "이 프로젝트의 목표는 무엇인가?"부터 시작해 질문을 던짐** (Plan-Execute 패턴).
- **Mob Elaboration (몹 정교화)**: 팀 전체가 AI 와 실시간 대화하며 요구사항을 구체화.
- 전통 기획 회의의 **70~80% 를 AI 가 대체** → 1~2 일 만에 검증된 백로그/유닛 완성 사례 다수.
- **핵심**: 맥락 (Context) 축적 → 다음 단계로 풍부한 시맨틱 컨텍스트 전달.

### 2 단계: Construction (구축/구현)

- 가장 많은 시간이 투입되는 단계지만, **AI 가 multi-file 수정·리팩토링·TDD 자동 생성까지 주도**.
- **Mob Construction (몹 구축)**: 개발자·아키텍트가 AI 제안을 실시간으로 리뷰·수정.
- **DDD(도메인 주도 설계), BDD, TDD 가 자연스럽게 통합됨**.
- 결과: **코드·테스트 커버리지 80%+ 자동 생성** 후 인간이 핵심 부분만 손봄.

### 3 단계: Operations (운영)

- **배포·IaC·모니터링까지 AI 가 제안·관리**.
- **Telemetry(로그·메트릭) 분석 후 AI 가 자동으로 "이 부분 개선 제안"** → 인간 승인 후 적용.
- 아직 (2026 년) 가장 성숙도가 낮은 단계지만, **AWS·Kiro 등 도구에서 빠르게 진화 중**.

---

## 왜 3 단계인가? (핵심 철학)

### 1. 단계 최소화 + 흐름 최대화

- 전통 SDLC 의 많은 **handover(인수인계) 를 제거** → AI 가 **persistent context(지속 맥락) 를 유지**.

### 2. Human-in-the-loop 최소화 but 필수

- **AI 주도** → 인간은 **"핵심 Gate"에서만 개입** (품질·보안·비즈니스 판단).

### 3. 모든 개발 경로 호환

- 신규 개발·리팩토링·버그 픽스·마이그레이션 등에 독단적이지 않음.

---

## 실무 적용 팁 (한국 기업 사례 기반)

### 성공 사례

- **웅진씽크빅 북큐레이터 AI 에이전트**처럼 Inception 에서 요구사항 → Construction 에서 코드 → Operations 에서 배포까지 **7 주 만에 완성** 사례 증가.

### 도구 조합

- **AWS Bedrock + Claude Code + Kiro + Linear + GitHub Actions** 등.

### 2026 년 트렌드

- **Inception 을 1~3 일로 압축** → **Construction 에서 60~80% 자동화** → **Operations 자동화 강화**.

---

## 요약

> AI-DLC 의 3 단계는 아직 실험·적용 초기지만, **"AI 가 계획을 세우고, 인간이 검증한다"**는 멘탈 모델로 가장 현실적인 전환 로드맵으로 평가받고 있습니다.

---

## 감리 관점에서의 시사점

정보시스템 감리 관점에서 AI-DLC 도입 시 고려사항:

1. **요구사항 검증**: AI 가 생성한 사용자 스토리와 NFR 의 적절성 검토
2. **코드 품질 게이트**: 자동 생성 코드의 보안·성능·유지보수성 검증 프로세스
3. **인간 개입 포인트**: 핵심 의사결정 시점 (Gate) 의 명확한 정의와 문서화
4. **추적성**: AI 제안 → 인간 승인 → 적용 이력의端到端 추적 가능성
5. **위험 관리**: AI 오토메이션 실패 시 대비책 (Fallback) 수립 여부
