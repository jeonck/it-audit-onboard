# NCP 기반 외부 연계 아키텍처

네이버 클라우드 플랫폼 (NCP) 환경에서 보안상 **Public Subnet**(외부 노출)과 **Private Subnet**(내부 망)을 엄격히 분리하는 것이 정석입니다.

제시하신 흐름을 NCP 컴포넌트에 대입한 구성을 정리해 드립니다.

---

## NCP 기반 외부 연계 아키텍처 흐름

| 단계 | NCP 서비스 명칭 | 역할 및 흐름 |
|------|----------------|-------------|
| **1. 관문** | **API Gateway** | 외부 호출 정문. 인증 (IAM/API Key), Throttling, 캐싱을 처리합니다. |
| **2. 연결** | **Private Domain/VPC** | API GW 에서 내부 VPC 로 진입하는 구간입니다. (Private 호스트 연결) |
| **3. 분산** | **Load Balancer **(Internal) | Private Subnet 내부에 위치하며, 들어온 요청을 Nginx 서버들로 배분합니다. |
| **4. 웹** | **Nginx **(Server/ACG) | Reverse Proxy 역할을 하며, 특정 포트 (예: 80, 443) 만 허용하도록 ACG(Access Control Group) 설정이 적용됩니다. |
| **5. 앱** | **WAS **(Server) | 실제 비즈니스 로직 (Java, Python 등) 이 구동됩니다. Nginx 로부터 요청을 전달받습니다. |
| **6. 저장** | **Cloud DB **(MySQL/MSSQL 등) | WAS 에서만 접근 가능한 별도 DB Subnet 에 위치하여 데이터를 관리합니다. |

## 💡 NCP 환경에서의 핵심 체크포인트

### 1. VPC & Subnet 설계

| Subnet 유형 | 위치 | 용도 |
|------------|------|------|
| **Public Subnet** | 외부와 통신 필요 | API GW 접점, 외부 LB |
| **Private Subnet** | 내부 망 | Nginx, WAS, DB 배치 (외부 직접 노출 차단) |

---

### 2. ACG (Access Control Group) 설정 (매우 중요)

NCP 의 핵심 보안 요소입니다. "**Chaining**(연쇄 허용) 설정"을 해야 안전합니다.

| 자원 | ACG 설정 |
|------|---------|
| **Nginx ACG** | Internal LB 의 IP 만 허용 |
| **WAS ACG** | Nginx 의 IP 만 허용 |
| **DB ACG** | WAS 의 IP 만 허용 |

```
┌─────────────────────────────────────────────────────────────────┐
│  ACG Chaining (연쇄 허용)                                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Internet → API GW → Internal LB → Nginx → WAS → DB            │
│                                                                 │
│  ✅ Nginx ACG: Internal LB IP 만 허용                          │
│  ✅ WAS ACG: Nginx IP 만 허용                                  │
│  ✅ DB ACG: WAS IP 만 허용                                     │
│                                                                 │
│  ❌ 0.0.0.0/0 (전체 개방) 금지                                │
└─────────────────────────────────────────────────────────────────┘
```

---

### 3. API Gateway 연동 방식

| 방식 | 설명 |
|------|------|
| **공인 IP Endpoint** | 일반적인 방식이지만 보안 주의 필요 |
| **내부망 전용 Endpoint** | 보안을 위해 권장 (특정 IP 대역만 허용) |

> NCP API Gateway 는 Endpoint 를 공인 IP 로 잡을 수도 있지만, 보안을 위해 **내부망 전용 Endpoint 를 생성**하거나 **특정 IP 대역만 허용**하도록 설정하는 것이 일반적입니다.

---

### 4. 인프라 구성 시 제언

#### 기존 구성 (Nginx + WAS 분리)

```
API GW → LB → Nginx → WAS → DB
```

**장점**:
- Reverse Proxy 를 통한 보안 계층 추가
- 정적 콘텐츠 캐싱
- SSL 종단 처리

**단점**:
- 관리 포인트 증가 (Nginx 서버 별도 운영)

---

#### 고도화 구성 (서버리스/컨테이너)

> 관리 포인트가 늘어나는 것이 부담스러우시다면 **NCP 의 Cloud Functions**나 **Kubernetes Service**(NKS)를 활용해 API Gateway 와 바로 연동하는 구조로 고도화하는 방법도 있습니다.

```
# 서버리스 구성
API GW → Cloud Functions → DB

# 컨테이너 구성
API GW → NKS (Kubernetes) → DB
```

**장점**:
- 인프라 관리 부담 감소
- 오토스케일링 내장
- 비용 효율성 (사용한 만큼만)

## 감리 관점에서의 시사점

정보시스템 감리 관점에서 NCP 아키텍처 검토 시 고려사항:

1. **보안 구역 분리**: Public/Private Subnet 엄격한 분리 여부
2. **ACG 설정 적정성**: 연쇄 허용 (Chaining) 설정으로 최소 권한 원칙 준수
3. **API Gateway 보안**: 인증/인가, Throttling, IP 제한 설정
4. **데이터 암호화**: 전송 중 (TLS/SSL) 및 저장 데이터 암호화
5. **로그 및 모니터링**: API GW, LB, WAS, DB 전 구간 로그 수집
6. **백업 및 복구**: DB 백업 정책 및 복구 절차 수립
