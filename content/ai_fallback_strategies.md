# AI 폴백 전략 (Fallback Strategies)

AI 아키텍처에서 **폴백 (Fallback) 전략**은 시스템의 **가용성 (Availability)**과 **신뢰성 (Reliability)**을 보장하기 위한 **최후의 방어선**입니다.

특정 모델의 장애, 속도 저하, 혹은 품질 미달 상황이 발생했을 때 **시스템이 중단되지 않고 대안을 찾는 메커니즘**을 의미합니다.

Compound AI System 의 안정성을 높이는 **4 가지 핵심 폴백 시나리오**를 정리해 드립니다.

---

## 1. 가용성 기반 폴백 (Availability Fallback)

특정 LLM 공급사 (API) 의 **서버 다운이나 타임아웃 발생 시 다른 모델로 즉시 전환**하는 방식입니다.

### 동작 방식

| 단계 | 설명 |
|------|------|
| **1** | Primary 모델 (예: GPT-4o) 호출이 실패 (HTTP 5xx 에러 등) |
| **2** | 즉시 Secondary 모델 (예: Claude 3.5 Sonnet) 로 요청을 재전송 |

### AI Gateway 역할

- 이 과정은 **사용자 모르게 AI Gateway 단에서 자동으로 처리**되어야 하며, 시스템 전체의 가용성을 유지합니다.

### Infrastructure 관점

- 특정 리전 (Region) 장애를 대비하여 **멀티 리전 또는 멀티 클라우드 모델 배치**를 고려합니다.

---

## 2. 품질 기반 폴백 (Quality-based Fallback / Cascade)

**하위 모델의 답변 품질이 사전에 정의된 기준에 못 미칠 경우, 상위 모델이 개입**하는 방식입니다.

### 동작 방식

```
1. 먼저 저렴한 모델 (예: GPT-4o mini) 이 답변을 생성합니다.

2. 생성된 답변에 대해 Self-Correction 또는 검증 루프를 돌려
   '신뢰도 점수 (Confidence Score)'를 계산합니다.

3. 점수가 임계치 (예: 70 점) 미만이면
   고성능 모델 (예: GPT-4o) 이 다시 답변을 생성합니다.
```

### 효과

> **평소에는 비용을 절감**하다가, **난이도가 높은 질문에 대해서만 고비용 모델**을 사용하여 품질을 보장합니다.

---

## 3. 속도 및 할당량 기반 폴백 (Latency & Quota Fallback)

**API 응답 속도가 급격히 느려지거나, 모델별 호출량 제한 (Rate Limit) 에 도달**했을 때 적용합니다.

### 동작 방식

| 상황 | 대응 |
|------|------|
| **응답 시간 초과** | 모델의 응답 시간이 설정된 SLA(예: 5 초) 를 초과하면 해당 요청을 취소하고 더 빠른 경량 모델로 전환 |
| **TPM 할당량 소진** | 특정 모델의 TPM(Tokens Per Minute) 할당량이 소진되면, 여유 할당량이 있는 다른 모델이나 다른 계정의 API 로 라우팅 |

### 장점

- **대규모 트래픽 상황에서도 사용자 경험 (UX) 이 저하되는 것을 방지**합니다.

---

## 4. 콘텐츠 가드레일 폴백 (Content Guardrail Fallback)

모델의 출력이 **안전 정책에 위배되어 차단**되었을 때, 시스템이 완전히 멈추지 않도록 하는 전략입니다.

### 동작 방식

출력 가드레일에서 **부적절한 콘텐츠가 감지되어 답변을 내보낼 수 없을 때**, 에러 메시지 대신 **미리 준비된 '안전한 정적 응답'** 또는 **'우회 답변'**을 제공합니다.

### 예시

> "죄송합니다, 요청하신 내용은 내부 정책상 답변이 어렵습니다. 대신 관련된 공식 가이드를 안내해 드릴까요?"

와 같은 응답으로 매끄럽게 연결합니다.

## 💡 폴백 전략 설계 시 고려사항 (Checklist)

| 고려 요소 | 설명 |
|----------|------|
| **State Consistency** | 폴백 발생 시 이전 대화 문맥 (Context) 이 유실되지 않도록 세션 관리가 필요합니다. |
| **Circuit Breaker** | 반복적인 장애 발생 시 해당 모델로의 요청을 잠시 차단하여 시스템 전체의 과부하를 막아야 합니다. |
| **Cost Awareness** | 고성능 모델로 폴백될 경우 예상보다 비용이 급증할 수 있으므로, **일일 예산 캡 (Cap)**을 설정해야 합니다. |
| **Logging & AAR** | 어떤 이유로 폴백이 발생했는지 기록하여, 향후 프롬프트 개선이나 모델 선택 로직 수정에 활용합니다. |

---

## 🎯 PDCA 사이클과의 연계

> 이러한 폴백 전략은 엔지니어님께서 강조하신 **PDCA 사이클** 중 **'Check'와 'Act' 단계**에서 핵심적인 역할을 합니다.

```
Plan  → 폴백 정책 및 임계치 설계
Do    → 폴백 메커니즘 구현 및 배포
Check → 폴백 발생 로그 분석 (AAR)
Act   → 프롬프트 개선, 모델 선택 로직 수정
```

## 감리 관점에서의 시사점

정보시스템 감리 관점에서 AI 폴백 전략 도입 시 고려사항:

1. **가용성 목표 검증**: 폴백 적용 전후 시스템 가용성 (SLA) 비교 (예: 99.9% → 99.99%)
2. **품질 일관성**: 폴백 발생 시 응답 품질 차이와 사용자 경험 영향도 분석
3. **비용 통제**: 폴백으로 인한 예상 외 비용 증가 모니터링과 예산 캡 운영 적절성
4. **서킷 브레이커 운영**: 반복 장애 시 자동 차단 메커니즘과 복구 절차 검증
5. **세션 무결성**: 폴백 발생 시 대화 문맥 유지와 데이터 일관성 확인
6. **폴백 로그 분석**: 폴백 발생 원인, 빈도, 패턴 분석과 지속적 개선 사이클 운영
