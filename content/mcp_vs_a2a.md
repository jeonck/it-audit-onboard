# MCP vs A2A: AI 프로토콜 비교 분석

**MCP **(Model Context Protocol)와 **A2A **(Agent-to-Agent)는 각각 **'도구 연결의 표준'**과 **'협업 지능의 표준'**으로 구분할 수 있습니다.

---

## 📊 MCP vs A2A 비교 분석

| 구분 | MCP (Model Context Protocol) | A2A (Agent-to-Agent Protocol) |
|------|-----------------------------|------------------------------|
| **핵심 목적** | 도구/데이터 연결 표준화 (N×M 문제 해결) | 에이전트 간 협업/위임 표준화 |
| **통신 대상** | AI 모델 ↔ 외부 도구/데이터 (Server) | AI 에이전트 ↔ AI 에이전트 |
| **핵심 가치** | Context 주입 & Tool 실행 | Intent 전달 & Task 위임 |
| **비유** | 에이전트에게 들려준 '만능 도구 상자' | 에이전트끼리 대화하는 '무전기/협업 툴' |
| **주요 요소** | Resources, Tools, Prompts | Handoff, Negotiation, Goal Sharing |
| **보안 초점** | 최소 권한 (ACL), 데이터 샌드박싱 | 신뢰 체인 (Trust), 권한 대행 (Delegation) |
| **인프라 비유** | USB-C 표준 (하드웨어 연결) | HTTP/gRPC (서비스 간 통신/통신 규약) |

## 1. 관계의 정의: "개인기 vs 팀워크"

### MCP (개인기)

> **에이전트 개인이 얼마나 많은 정보에 접근하고 도구를 다룰 수 있는지 결정**합니다.

예를 들어, **agent-browser 를 다루는 능력**은 MCP 서버를 통해 부여됩니다.

```
┌─────────────────────────────────────────────────────────┐
│  MCP: 에이전트의 개인기                                 │
├─────────────────────────────────────────────────────────┤
│  ┌─────────────┐                                        │
│  │  AI Agent   │                                        │
│  │  (단일)     │                                        │
│  └──────┬──────┘                                        │
│         │ MCP Protocol                                 │
│         ↓                                               │
│  ┌─────────────────────────────────────────┐           │
│  │  MCP Servers (도구/데이터)              │           │
│  │  - agent-browser (웹 브라우징)          │           │
│  │  - filesystem (파일 접근)               │           │
│  │  - database (DB 쿼리)                   │           │
│  │  - api-client (외부 API)                │           │
│  └─────────────────────────────────────────┘           │
│                                                         │
│  → 에이전트 하나의 능력 확장                            │
└─────────────────────────────────────────────────────────┘
```

---

### A2A (팀워크)

> **에이전트가 자기가 못하는 일을 누구에게 맡길지, 그리고 그 결과를 어떻게 받을지 결정**합니다.

예를 들어, **"나는 브라우징 **(MCP)라고 소통하는 규칙입니다.

```
┌─────────────────────────────────────────────────────────┐
│  A2A: 에이전트 간 팀워크                                │
├─────────────────────────────────────────────────────────┤
│  ┌─────────────┐         A2A Protocol         ┌─────────────┐ │
│  │  Browser    │ ←──────────────────────────→ │   Coder     │ │
│  │   Agent     │    "정보 찾을게,             │   Agent     │ │
│  │  (MCP:      │     너는 구축해줘"           │  (MCP:      │ │
│  │  browser)   │                              │  ide)       │ │
│  └─────────────┘                              └─────────────┘ │
│         ↓                      ↓                      ↓       │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │  MCP Servers (각 에이전트의 개인 도구)                  │ │
│  │  - browser: agent-browser                               │ │
│  │  - coder: IDE, compiler, git                            │ │
│  └─────────────────────────────────────────────────────────┘ │
│                                                               │
│  → 여러 에이전트 협업                                       │
└─────────────────────────────────────────────────────────┘
```

## 2. 상세 비교

### 통신 패턴

| MCP 통신 패턴 | A2A 통신 패턴 |
|--------------|--------------|
| **단방향**: Agent → Server | **양방향**: Agent ↔ Agent |
| **요청 -응답**: Tool Call → Result | **협상**: Proposal → Counter → Agreement |
| **수동 실행**: 에이전트가 도구 호출 | **자율 위임**: 에이전트가 작업 양도 |

---

### 워크플로우 예시

#### MCP 워크플로우 (단일 에이전트)

```
1. User: "이 버그 수정해줘"
         ↓
2. AI Agent (MCP 활용)
   - MCP: filesystem → 코드 읽기
   - MCP: ide → 수정사항 적용
   - MCP: terminal → 테스트 실행
         ↓
3. Result: "버그 수정 완료"
```

---

#### A2A 워크플로우 (다중 에이전트 협업)

```
1. User: "이 서비스 배포해줘"
         ↓
2. Manager Agent (A2A 조율)
   - A2A → Coder Agent: "코드 빌드해줘"
   - A2A → Tester Agent: "테스트 실행해줘"
   - A2A → Deploy Agent: "프로덕션에 배포해줘"
         ↓
   ← Coder: "빌드 완료"
   ← Tester: "테스트 통과"
   ← Deploy: "배포 완료"
         ↓
3. Result: "서비스 배포 완료"
```

## 3. 보안 모델 비교

### MCP 보안 (수직적 통제)

| 요소 | 설명 |
|------|------|
| **최소 권한 **(ACL) | 각 MCP Server 는 허용된 Resource/Tool 만 노출 |
| **데이터 샌드박싱** | 파일시스템, DB 접근 범위 제한 |
| **인증/인가** | MCP Client-Server 간 인증 (API Key, OAuth 등) |

```
┌─────────────────────────────────────────────────────────┐
│  MCP 보안 모델                                          │
├─────────────────────────────────────────────────────────┤
│  AI Agent                                               │
│      ↓                                                  │
│  ┌─────────────────────────────────────────┐           │
│  │  MCP Server (샌드박스)                  │           │
│  │  ✅ 허용: /home/user/project/*          │           │
│  │  ❌ 차단: /etc/*, /root/*               │           │
│  └─────────────────────────────────────────┘           │
└─────────────────────────────────────────────────────────┘
```

---

### A2A 보안 (수평적 신뢰)

| 요소 | 설명 |
|------|------|
| **신뢰 체인 **(Trust Chain) | 에이전트 간 신원 검증과 신뢰 수준 계층화 |
| **권한 대행 **(Delegation) | 사용자 권한의 제한적 위임과 추적 |
| **감사 로그** | 에이전트 간 모든 대화와 위임 기록 보존 |

```
┌─────────────────────────────────────────────────────────┐
│  A2A 보안 모델                                          │
├─────────────────────────────────────────────────────────┤
│  Manager Agent (신뢰 수준: 높음)                        │
│      ↓ A2A (신뢰 검증)                                  │
│  Worker Agent (신뢰 수준: 중간)                         │
│      ↓ 권한 위임 (제한적)                               │
│  External Agent (신뢰 수준: 낮음)                       │
│                                                         │
│  모든 통신 감사 로그 기록                              │
└─────────────────────────────────────────────────────────┘
```

## 4. 실무 적용 시나리오

### 시나리오 1: 단일 에이전트 + MCP

> **간단한 작업은 MCP 로 충분**합니다.

```
작업: "GitHub 이슈 #123 확인해줘"

MCP 활용:
- github MCP Server → 이슈 조회
- slack MCP Server → 팀에 알림

→ 단일 에이전트로 충분
```

---

### 시나리오 2: 다중 에이전트 + MCP + A2A

> **복잡한 작업은 A2A 협업이 필요**합니다.

```
작업: "새 기능 개발해서 배포해줘"

A2A + MCP 활용:
┌─────────────────────────────────────────────────────────┐
│  Manager Agent (조정)                                   │
│      ↓ A2A                                              │
│  ├─→ Planner Agent (MCP: jira) → 작업 분해            │
│  ├─→ Coder Agent (MCP: ide, git) → 코드 작성          │
│  ├─→ Tester Agent (MCP: pytest) → 테스트 실행         │
│  └─→ Deploy Agent (MCP: kubernetes) → 배포            │
└─────────────────────────────────────────────────────────┘

→ 다중 에이전트 협업 필요
```

## 📋 선택 가이드: MCP vs A2A

| 상황 | 권장 방식 | 이유 |
|------|----------|------|
| **단일 에이전트 확장** | MCP | 도구/데이터 접근만 필요 |
| **전문가 에이전트 협업** | A2A | 각기 다른 전문성 결합 필요 |
| **간단한 자동화** | MCP | 오버헤드 최소화 |
| **복잡한 워크플로우** | A2A + MCP | 협업 + 도구 접근 모두 필요 |
| **보안 경계 명확화** | MCP | 샌드박스 통제가 용이 |
| **권한 위임 필요** | A2A | 신뢰 체인과 권한 대행 필요 |

## 💡 엔지니어링 인사이트

> **MCP 는 에이전트의 '손과 발'**이고, **A2A 는 에이전트 간의 '입과 귀'**입니다.

현실적인 AI 시스템 아키텍처는 **두 프로토콜을 모두 활용**하는 하이브리드 형태가 될 것입니다:

```
┌─────────────────────────────────────────────────────────┐
│  하이브리드 AI 아키텍처                                  │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌─────────────┐    A2A    ┌─────────────┐             │
│  │  Agent A    │ ←────────→ │  Agent B    │             │
│  └──────┬──────┘             └──────┬──────┘             │
│         │ MCP                       │ MCP                 │
│         ↓                           ↓                     │
│  ┌─────────────┐             ┌─────────────┐             │
│  │ MCP Servers │             │ MCP Servers │             │
│  │ (도구/데이터)│             │ (도구/데이터)│             │
│  └─────────────┘             └─────────────┘             │
│                                                         │
│  → MCP: 개별 에이전트 능력 확장                        │
│  → A2A: 에이전트 간 협업 조정                          │
└─────────────────────────────────────────────────────────┘
```

## 감리 관점에서의 시사점

정보시스템 감리 관점에서 MCP vs A2A 검토 시 고려사항:

1. **프로토콜 성숙도**: MCP 는 Anthropic 주도 표준화 진행 중, A2A 는 초기 단계
2. **보안 경계**: MCP 는 수직적 통제 (샌드박스), A2A 는 수평적 신뢰 (신원검증)
3. **감사 추적성**: MCP 는 Tool Call 로그, A2A 는 에이전트 간 대화 로그 모두 필요
4. **책임 소재**: MCP 는 단일 에이전트 책임, A2A 는 다중 에이전트 책임 분산
5. **상호운용성**: MCP 는 벤더 중립 지향, A2A 는 표준화 진행 중
6. **복잡도 관리**: MCP 는 N+M 복잡도, A2A 는 에이전트 간 조정 오버헤드 추가
