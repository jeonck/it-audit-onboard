# RAGAS: RAG 품질 평가 프레임워크

AI 서비스의 신뢰성을 정량적으로 평가하고 싶으실 때 가장 먼저 마주하게 되는 표준 프레임워크가 바로 **RAGAS **(RAG Assessment)입니다.

엔지니어님께서 강조하신 **PDCA **(Plan-Do-Check-Act)에서 **'Check**(검증)를 자동화해 주는 핵심 엔진이라고 이해하시면 됩니다.

---

## 1. RAGAS 의 핵심: "RAG 의 3 요소 평가"

RAGAS 는 단순한 정성적 평가를 넘어, RAG 파이프라인의 각 연결 고리를 **수학적/논리적 지표**로 점검합니다.

이를 흔히 **'RAG Triad'**라고 부릅니다.

---

### ① Faithfulness (충실도)

> **질문**: "모델의 답변이 추출된 컨텍스트에만 근거하고 있는가?"

| 항목 | 설명 |
|------|------|
| **측정 목적** | 환각 (Hallucination) 여부 체크 |
| **판단 기준** | 컨텍스트에 없는 내용을 지어냈다면 점수 낮음 |
| **점수 범위** | 0~1 (1 일수록 우수) |

#### 보안 전문가의 시각

> 폐쇄형 AI 시스템에서 **내부 규정에 없는 내용을 AI 가 임의로 답하지 않도록 통제**하는 지표입니다.

```
┌─────────────────────────────────────────────────────────┐
│  Faithfulness 평가 예시                                 │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  질문: "회사의 휴가 규정은 어떻게 되나요?"             │
│                                                         │
│  컨텍스트: "연차휴가는 1 년 근무 시 15 일 부여"        │
│                                                         │
│  모델 답변 A: "연차휴가는 1 년 근무 시 15 일입니다."   │
│  → Faithfulness: 1.0 ✅ (컨텍스트 기반)                │
│                                                         │
│  모델 답변 B: "연차휴가 15 일에 반차도 2 회 있습니다." │
│  → Faithfulness: 0.5 ❌ (반차 정보 없음)               │
└─────────────────────────────────────────────────────────┘
```

---

### ② Answer Relevance (답변 관련성)

> **질문**: "답변이 사용자의 원래 질문에 대해 얼마나 직접적인 해결책을 제시하는가?"

| 항목 | 설명 |
|------|------|
| **측정 목적** | 질문 의도와의 일치도 |
| **판단 기준** | 논리적으로 맞더라도 질문과 동떨어져 있으면 점수 낮음 |
| **점수 범위** | 0~1 (1 일수록 우수) |

```
┌─────────────────────────────────────────────────────────┐
│  Answer Relevance 평가 예시                             │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  질문: "AWS 에서 S3 버킷을 생성하는 방법은?"           │
│                                                         │
│  답변 A: "AWS Console 에서 S3 이동 → 버킷 생성 클릭"   │
│  → Relevance: 0.95 ✅ (직접적 해결책)                  │
│                                                         │
│  답변 B: "S3 는 Simple Storage Service 의 약자입니다." │
│  → Relevance: 0.3 ❌ (질문 의도와 동떨어짐)            │
└─────────────────────────────────────────────────────────┘
```

---

### ③ Context Precision & Recall (컨텍스트 정확도 및 재현율)

> **질문**: "검색된 문서들이 질문에 답하는 데 정말 유용한 정보였는가?"

| 항목 | 설명 |
|------|------|
| **측정 목적** | 데이터 계층 (Vector DB/MCP) 성능 평가 |
| **판단 기준** | Garbage In, Garbage Out - 쓰레기 정보가 들어오면 좋은 답 불가 |
| **점수 범위** | 0~1 (1 일수록 우수) |

#### 세부 지표

| 지표 | 설명 |
|------|------|
| **Context Precision** | 관련 문서가 상위 순위로 잘 검색되었는가? |
| **Context Recall** | 필요한 문서가 누락 없이 모두 검색되었는가? |

```
┌─────────────────────────────────────────────────────────┐
│  Context Precision & Recall 평가 예시                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  질문: "2024 년 보안 감사 일정은?"                     │
│                                                         │
│  검색된 문서:                                           │
│  1. [상위] 2023 년 감사 일정 (구정보) ❌              │
│  2. [중위] 2024 년 보안 감사 계획 (정답) ✅           │
│  3. [하위] 2024 년 인사 평가 기준 (무관) ❌           │
│                                                         │
│  → Context Precision: 0.33 (정답이 2 순위)             │
│  → Context Recall: 1.0 (정답 문서 포함)                │
└─────────────────────────────────────────────────────────┘
```

## 2. RAGAS 평가 지표 요약

| 지표 | 측정 대상 | 핵심 질문 | 우수 기준 |
|------|----------|----------|----------|
| **Faithfulness** | 모델 추론 | 컨텍스트 기반인가? | > 0.8 |
| **Answer Relevance** | 답변 품질 | 질문 의도와 일치하는가? | > 0.7 |
| **Context Precision** | 검색 순위 | 관련 문서가 상위에 있는가? | > 0.7 |
| **Context Recall** | 검색 완전성 | 필요한 문서가 모두 검색되었는가? | > 0.8 |
| **Answer Similarity** | 답변 일관성 | 기준 답변과 유사한가? | > 0.7 |

## 3. AI Observability 와의 결합: "실시간 품질 감사"

RAGAS 를 **Observability 시스템** (예: Arize Phoenix, LangSmith)에 통합하면 다음과 같은 페인 포인트를 해결할 수 있습니다.

### 해결하고 싶은 사항 #1: 모델 업데이트 공포

| 문제 | RAGAS 기반 해결책 |
|------|------------------|
| 모델 교체 시 품질 저하 우려 | 모델 교체 (예: Claude 3 → 3.5) 할 때 **RAGAS 점수 변화**를 측정하여 **회귀 테스트 **(Regression Test) |

```
┌─────────────────────────────────────────────────────────┐
│  모델 교체 회귀 테스트                                  │
├─────────────────────────────────────────────────────────┤
│                                                         │
│ 基准 모델: Claude 3                                     │
│  - Faithfulness: 0.85                                   │
│  - Relevance: 0.78                                      │
│  - Context Precision: 0.72                              │
│                                                         │
│  신규 모델: Claude 3.5                                  │
│  - Faithfulness: 0.88 ✅ (+0.03)                        │
│  - Relevance: 0.82 ✅ (+0.04)                           │
│  - Context Precision: 0.71 ⚠️ (-0.01)                  │
│                                                         │
│  → 전체 점수 향상 → 배포 승인 ✅                       │
└─────────────────────────────────────────────────────────┘
```

### 해결하고 싶은 사항 #2: 비용 최적화

| 문제 | RAGAS 기반 해결책 |
|------|------------------|
| 과도하게 긴 컨텍스트 주입 | **Context Precision**을 체크하여, 불필요한 토큰 소모를 유발하는 문서 필터링 |

```
┌─────────────────────────────────────────────────────────┐

│  - Context Precision: 0.40 (낮음)                       │
│  - 비용: $0.50/쿼리                                    │
│                                                         │
│  최적화 후:                                             │
│  - 검색 문서: 3 개 (15,000 tokens)                     │
│  - Context Precision: 0.85 (향상)                       │
│  - 비용: $0.15/쿼리 (70% 절감)                         │
└─────────────────────────────────────────────────────────┘
```

### Continuous Monitoring (지속적 모니터링)

> 운영 중인 **MiroFish 에이전트**가 답변을 내놓을 때마다 **백그라운드에서 RAGAS 점수**를 계산하고, **0.7 점 이하로 떨어지면 운영자에게 즉시 알람**을 보내는 **'품질 가드레일'**로 활용하십시오.

```
┌─────────────────────────────────────────────────────────┐
│  실시간 품질 모니터링                                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. MiroFish 에이전트 답변 생성                        │
│         ↓                                               │
│  2. 백그라운드에서 RAGAS 점수 계산 (비동기)            │
│         ↓                                               │
│  3. 점수 체크:                                          │
│     - 0.7 이상: 정상 로그 기록                         │
│     - 0.7 미만: 🚨 운영자에게 알림 (Slack, Email)      │
│         ↓                                               │
│  4. AAR 자동 생성: 실패 사례 분석 및 개선 권고         │
└─────────────────────────────────────────────────────────┘
```

| **Faithfulness** | < 0.7 | < 0.5 |
| **Answer Relevance** | < 0.6 | < 0.4 |

## 5. RAGAS 구현 예시 (Python)

```python
from ragas import evaluate
from ragas.metrics import (
    faithfulness,
    answer_relevancy,
    context_precision,
    context_recall,
)
from datasets import Dataset

# 평가 데이터셋
eval_data = {
    "question": ["회사의 휴가 규정은?"],
    "answer": ["연차휴가는 1 년 근무 시 15 일입니다."],
    "contexts": [["연차휴가는 1 년 근무 시 15 일 부여"]],
    "ground_truth": ["15 일"]
}

dataset = Dataset.from_dict(eval_data)

# 평가 실행
result = evaluate(
    dataset,
    metrics=[
        faithfulness,
        answer_relevancy,
        context_precision,
        context_recall,
    ]
)

print(result)
# faithfulness: 0.95
# answer_relevancy: 0.88
# context_precision: 0.85
# context_recall: 0.90
```

## 감리 관점에서의 시사점

정보시스템 감리 관점에서 RAGAS 도입 검토 시 고려사항:

1. **정량적 품질 지표**: Faithfulness, Relevance 등 수치화된 품질 기준
2. **회귀 테스트 자동화**: 모델 업데이트 시 품질 저하 방지
3. **근본 원인 분석**: 검색 실패 vs 모델 추론 실패 명확한 판별
4. **비용 최적화**: Context Precision 기반 불필요한 토큰 소모 방지
5. **실시간 모니터링**: 품질 가드레일과 자동 알림 시스템
6. **보안 고려**: 폐쇄형 시스템용 사내 평가 모델 구축
